## 一、控制结构：云台**开环**，没有云台角度反馈

```
   速度指令(0x04, rad/s) = 几何前馈 + 视觉 P          两路同量纲，直接相加
```

| 项 | 来源 | 作用 |
|---|---|---|
| 几何前馈 | 陀螺测**车体**偏航角 ψ → 反推车在椭圆弧上的位置 → 靶方位角变化率 `guidance_ff()` | 车头自己转的那一份在指令里**扣掉** |
| 视觉 P | `AIM_GAIN_RATE × err_x`（经 2 态卡尔曼） | 只管静态残差，越靠近靶心速度越小 |

**QD4310 的速度是"转子相对定子"**，而定子螺栓固定在车架上 —— 所以车头自己转的那一份必须由前馈扣掉，否则云台跟着车头跑。

**没有速率自稳环**：陀螺装在**车体**上测 ψ，不是测云台。旧文档里的 `GYRO_RATE_K` / 速率环 / 航向环**全部已废弃**，代码里不存在。

**初始定位**：进弯用 `0x05` 绝对角定位 300 ms（`SYNC_MAX_TICKS=60`），之后交棒给前馈+视觉。
开机序列 `清错误(0xFB) → 使能(0x01) → 回零(0x05→0°)`，等 500 ms 再放行瞄准 —— 否则第一条 `0x04` 会把回零的位置环半路切走。**`0xFE` 绝不能发**，会覆盖上位机标定的零点。

**发送**：收到新视觉帧立刻发（事件驱动，延迟降到 0~1 ms），`SEND_PERIOD_TICKS=5 ms` 只在视觉断流时兜底。
⚠️ 速度模式下补帧**不能发 `0x00`**（那是"保持上一拍速度"），必须显式发一条 0 速度。

| `AIM_GAIN_RATE` | **0.023** rad/(px·s) | = λ/(f·T_视觉)。λ = 0.023×290×0.018 = **0.120**（>0.25 才振铃，余量 2×） |

### 符号约定（2026-10-04 **已整车实测确认，三个全对，不要动**）

| 符号 | 值 | 含义与验证方法 |
|---|---|---|
| `MOTOR_DIR_SIGN` | **+1.0** | 电机正转方向 = 逆时针 = 目标右移方向，三者同号共用。发正速度云台沿逆时针转（手册 5.3.2.1 + 上位机调参实测一致） |
| `GYRO_RATE_SIGN` | **-1.0** | 模块的原始 `GyroZ` 与模块 `Yaw` 角 **反号**。`PSI_RATE() = GYRO_RATE_SIGN × yaw_rate_lpf × DEG2RAD`。验证：手转车体，`GyroZ`（`R` 列）持续为正时 `psi` 应在下跌 |
| 视觉误差 | 增益为**正** | `err_x = 靶心 − 激光点`（像素），`w += AIM_GAIN_RATE × err_x` 直接相加、**不取反**。验证：靶心出现在画面右侧（err_x > 0）时，云台应向右追，`err_x` 单调回零 |

三个符号是**一条链**：视觉 P 的符号 ⟷ 电机转向 ⟷ 陀螺反号，任意一个翻掉整条环就变成正反馈。既然已经实测确认，**换电机、换陀螺安装朝向、换相机方向之后都要重新验一遍这三个**（走上面三条验证法即可，不用重新推导）。

**待标定**：`LASER_X_PX`（⛔ 没激光笔）· `GYRO_LSB_PER_DPS`（占位 16.4）· MaixCam 处理延迟（预估 ~20 ms，检测 18.5 ms）

**焦距已实测**：`f = 290` px（2026-09-28）。校验法：靶纸平移 50 mm @1m → `err_x` 变化 ≈14.5 px。水平视场 ≈71°，垂直 ≈48°。

## 三、MaixCam2 侧（`rectangle/`，入口 `main.py`）

**上电两阶段**：

```
① 相机切 416×416 → YOLOv5 数字模型（最多 10 s）→ 连续多帧同一数字才算认出
② 把 N 发给底盘（重复 3 s，不等 ACK）→ 相机切回 416×260
③ 矩形识别瞄准，每帧把 err_x 发给云台，跑到底
```

| 要点 | 说明 |
|---|---|
| **为什么要切分辨率** | 数字模型要 416×416 方形；矩形那套阈值**全按 416×260 标定**，换分辨率就作废 |
| **切回后不重锁曝光** | ISP 不会重置，`EXPOSURE_US = 5000` 只在开机锁一次 |
| **标签陷阱** | 模型 `labels = ["3","1","2","4"]`，必须 `labels[class_id]` 反查，**别写 `class_id+1`**（会把 3 当 1，停错点位） |
| **底盘协议** | `AA 55 'N' <digit> <sum>` 5 字节，**没有 ACK**，重复发 3 秒；`digit=0` = 没认出来 |
| **两路串口** | UART4 `A21/A22`→云台（每帧 err_x）；UART1 `A30/A31`→底盘（只在认出时发） |

**矩形识别关键常量**（`no_canny.py`）：`USE_CANNY=False` · `CAM 416×260` · `MIN_AREA=1300` · 内外框比 `0.68 ~ 0.82` · `PROFILE=False`（只显示一行 fps）
内外框比物理值：A4 外框 297×210 − 18 mm 胶带 = 内孔 261×174 → **0.728**；框宽 t=12 mm→0.814、10 mm→0.844。0.68~0.82 ≈ 只接受框宽约 10.5~21 mm。
实测帧率：416×260 → detect 18.5 ms → **~53 fps**；512×320 → 25.8 ms → 36 fps。
**MaixPy UART API**：`read()` 有数据立刻返回、`read(len, timeout)`、`write()`/`write_str()`；**没有 `any()`**；用了 `set_received_callback` 就不能再 `read()`。

**✅ 两阶段流程已在车上实测通过**（2026-10-04 确认）：`set_resolution` 切换正常、数字识别与 N 值发送正常、切回 416×260 后矩形识别正常。三块板各自的链路（UART3 视觉 / UART2 陀螺 / UART1 云台）均已上板验证。

## 四、关键结论（踩过的坑）

| # | 结论 |
|---|---|
| 1 | **模块的 Yaw 与 GyroZ 符号相反** —— 实测手转时 gZ 持续为正而 yaw100 下跌。不翻符号 = 正反馈 |
| 2 | **卡尔曼比一阶低通好得多** —— 匀速目标下滞后 0 px，低通 α=0.5 是 6 px（1.27°，1.25 m 处 2.8 cm） |
| 3 | **纯速率环走不通** —— 实测 K=0.3 震 / 0.15 轻微震 / 0 不震但自稳也没了。增益硬上限 1.0（= 回路纯延迟决定的 `1+Ke^(−sτ)=0`），100 Hz 陀螺 τ≈10 ms → 临界 50 Hz。**这是数据率决定的物理限制，调参突破不了** |
| 4 | **自稳的病根在内环**（QD4310 内部速度环），不在外环。当前内部环参数（2026-10-04 上位机读出）：角度环 kp=150 ki=0 kd=0，速度环 kp=0.030 ki=0.39 kd=0 —— **0.39 是调好的好参数** |
| 5 | **云台无限位**（可 360° 连续转）—— 找靶扫描不受角度限制 |
| 6 | **模块 Yaw 不慢漂**（实测），6 轴 IMU 常见的漂移在这个模块上可忽略 |
| 7 | 陀螺模块**内部已做融合滤波**（Yaw 那条路），GyroZ 是原始值，只做阻尼时无需再滤 |
| 8 | 天猛星供电：排针 `5V` **直连 USB VBUS**，可外部 5V 灌，**必须共地**（走 QD4310 的 SH1.0 G 线或 24V 负极） |
| 9 | **100 Hz 是陀螺模块固件写死的** —— 协议里没有任何频率/带宽设置指令（CMD 只有 0x01/0x0A/0x0B/0x10/0x12/0x14/0xF0） |

**B 路线（只在 A 量化后明显超标才做）**：换**裸 ICM42688 直连 SPI**（模块 MCU → MSPM0 直接读，115200 UART → 8 MHz SPI，100 Hz → 可设 32 kHz，延迟 10 ms → 1 ms，可用增益上限 1.0 → ≈10）。
参考实现在工作区外 `…/底盘代码/SeekFree_MSPM0G3507_Opensource_Library/project/code/ICM_42688.c`（硬件 SPI，引脚 **B23/B22/B21**，实际设 200 Hz）。
**这三个引脚本工程全空着**，硬件不用挪东西。成本：模块 ¥20~30 + SysConfig 加 SPI + 移植驱动 + 重做零偏标定。
决策依据：**先走 A（量化自稳精度），够指标就收工。**

## 五、经验备忘（旧文档删掉后仅存这几条）

| 条 | 内容 |
|---|---|
| **MSPM0 + SysConfig 的 NVIC 坑** | SysConfig **只生成外设级中断使能**（`DL_UART_Main_enableInterrupt`），**NVIC 那层不生成**，必须自己在 init 里调 `NVIC_EnableIRQ(UART_x_INST_INT_IRQN)`。漏了的后果：**中断永不触发、数据卡在 FIFO、一个字节都收不到，而编译期和运行期都不报任何错**。本项目踩过两次（MCAN 一次、UART3 视觉一次）。位置：`gimbal.c: gimbal_init()` / `gyro_link.c: gyro_link_init()` / `vision_link.c: vision_link_init()` / `debug_uart.c: debug_uart_init()` |
| **速率环的延迟天花板** | 回路纯延迟 τ 决定增益硬上限：`1 + K·e^(−sτ) = 0` → K<1 稳定 / K=1 临界（f=1/(2τ)）/ K>1 发散。100 Hz 陀螺 τ≈10 ms → 临界 50 Hz，且 `ω_云台 = ω_车体/(1+K)`，**K=1 也只能把扰动减半**。江南方案陀螺 1000 Hz（τ≈1 ms）所以能用大增益 —— 差别全在数据率 |
| **`GYRO_LSB_PER_DPS` 量纲** | `gyro_link.h` 里是 **16.4**（占位）。标法：匀速转一整圈 360° 记时间 T，比调试行的 &#124;R&#124;（×10）与 `360/T` |
| **符号三个全对（已整车实测）** | `MOTOR_DIR_SIGN=+1.0` / `GYRO_RATE_SIGN=-1.0` / 视觉 P 不取反 —— 2026-10-04 用户确认当前工程参数与符号全部正确。**只要不动硬件就不用再验**；换电机、换陀螺安装朝向、换相机方向后走 §二 那三条验证法重验一遍 |
| **SDK 文档 CRC 覆盖范围没写** | 控制包 4 字节 / 反馈包 9 字节这个假设是从手册推的，BUGS #1 的候选原因之一 |
