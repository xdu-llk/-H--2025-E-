## 一、系统构成与分工

```
 MaixCam2 ──UART3(PB2/PB3) 6字节 err_x──→ MSPM0G3507 ──UART1(PA8/PA9)──→ QD4310 云台
     │                                      ↑
     │ UART1(A30/A31) 5字节 数字N        UART2(PB17/PB18) 100Hz
     ↓                                      │
 底盘主控（循迹/电机/定点停车）          汇电籽-601 陀螺（装在【车体】上，测车体偏航 ψ）
```

**本板只负责视觉对准云台**；循迹、电机、定点停车全归底盘主控。

> ⚠️ 旧文档把 UART3 写成 PINCM50/51、晶振写成 PINCM45/46 —— 那是错的（PB2/PB3 = PINCM15/16，PA5/PA6 = PINCM10/11）。现已按生成代码修正。

### 注意

- ⚠️ **PA2 是 ROSC 脚**。原理图标注「PA2/ROSC 精度很重要」，板子预留了提升 SYSOSC 精度的精密电阻，但**我们把 PA2 分给了激光，ROSC 未启用**。若以后某路串口偶发误码，第一件可试的就是启用 ROSC（把激光挪脚）。
- ⚠️ **HFXT 40 MHz 晶振是"僵尸"**：它当初只为 CANCLK 服务，CAN 删除后没人用了，但生成的代码仍会开它，**开机多等 640 µs 起振还白耗电**。要关就在 SysConfig 改三处：`useHFCLK_Manual=false`、`HFXT.enable=false`、`EXHFMUX` 回 Digital。
- **CAN 已从 SysConfig 删除**，PA12/PA13 释放；旧驱动停在 `gimbal_can.c.disabled`，不编译。
- 本板**不是 TI LaunchPad**：`LP-MSPM0G3507` 的排针布局与本板完全不同，套用会得到"能编译但引脚错位"的固件。只从 SDK 取 MSPM0G3507 **器件**特性，引脚从 SysConfig pinmux 取。

## 四、云台 QD4310

| 项 | 值 |
|---|---|
| 通信 | **UART**（不是 CAN），115200 8N1 |
| 设备 ID | **0** |
| 硬件 / 固件 | 4310_6.2.1 / Software 6.4.0 |
| 内部环 | 角度环 kp=**150** ki=0 kd=0；速度环 kp=**0.030** ki=**0.39** kd=0（2026-10-04 从上位机读出，**当前实跑值**；0.39 是调好的好参数，别再往下压） |
| 限幅 | current 1.65 A，speed 1000 rpm |

⚠️ 内部参数由厂家上位机改、存在电机里，**不在代码里**；改完必须点「储存」，否则断电回原值。以后要查以**上位机读出来的为准**。

**两个环各管一种指令模式**（2026-10-04 确认）：
- **速度环（0.030 / 0.39 / 0）** ← 平时瞄准用的 `0x04` 速度指令模式（几何前馈 + 视觉 P）
- **角度环（150 / 0 / 0）** ← 进弯时 `0x05` 绝对角定位，一次定位到目标角，已经实测没问题

### 接线（SH1.0-3Pin）

```
QD4310 T (TX) ──→ MSPM0 PA9   (UART1_RX)
QD4310 R (RX) ←── MSPM0 PA8   (UART1_TX)
QD4310 G     ──── MSPM0 GND
QD4310 XT30  ──── 24V 电源
```

### 数据包（手册 6.2.2 / 6.2.3）

**UART 包 = `[ID] + [CAN 包原样] + [CRC8]`**

| | 长度 | 布局 |
|---|---|---|
| 控制包 | 5 | `ID, 指令类型, 控制量(2, 小端), CRC8` |
| 反馈包 | 10 | `ID, 电机状态, 错误码, 电流(2), 转速(2), 角度(2), CRC8` |

- **CRC8**：多项式 `0x07`、初值 `0x00`、异或 `0x00`、不反转（标准 MSB-first CRC-8）。
  ⚠️ 手册**没写覆盖范围**，本工程按"包内 CRC 之前的全部字节"（控制 4 / 反馈 9）处理。
- **指令码**：`0x01`使能 `0x02`失能 `0x03`电流 `0x04`速度 `0x05`角度 `0x06`低速 `0x07`角度步进 `0xFB`清错误 `0xFE`置零 `0xFF`重启
- **控制量编码**（手册 5.3.2.1，⚠️ 两个角度指令的满量程不一样）：

| 指令 | 类型 | 换算 | 满量程 |
|---|---|---|---|
| `0x05` 角度控制 | **uint16** | `raw = θ/(2π) × 65535` | 65535 |
| `0x07` 角度步进 | int16 | `raw = Δθ/(2π) × 32767` | ±32767 |
| `0x04` 速度 | int16 | `raw = rpm/1000 × 32767` | ±32767 |
| `0x03` 电流 | int16 | `raw = A/10 × 32767` | ±32767 |

### ⚠️ 一发一收（最容易踩的坑）

手册 6.2.3：**发一条 → 等反馈或超时 → 才能发下一条，严禁收发异步。**

所以**两条指令不能背靠背发**（`gimbal_clear_error(); gimbal_enable();` 里第二条必然被"还在等反馈"挡掉，**且不报任何错**）。本工程用状态机（`empty.c` 的 `gim_step`）每拍推进一步，不依赖任何"猜多久够"的延时。

另外：**等待窗口必须覆盖整个发送周期**（`GIMBAL_RX_TIMEOUT_TICKS == SEND_PERIOD_TICKS`，现在两边都是 **5 拍 = 5 ms**），否则留出 IDLE 空档，落进去的字节全丢，帧永远攒不齐（表现：`RB` 在涨但 `M=ME=0`）。

## 五、陀螺 汇电籽-601

| 项 | 值 |
|---|---|
| 芯片 | ICM42688 |
| 通信 | UART 115200 8N1，电平 **3.3V**（直连，不用电平转换） |
| 设备 ID | `0x60` |
| 回报率 | **100 Hz（固件写死，协议无频率指令）** |

### 接线

```
模块 V (5V) ──── 5V
模块 T (TX) ────→ MSPM0 PB18  (UART2_RX)
模块 R (RX) ←──── MSPM0 PB17  (UART2_TX)   ← 必须接！
模块 G      ──── GND
```

⚠️ **这是双向的**：模块默认不上报，靠开机发两条指令叫醒。**PB17 不接 → 指令到不了 → `G` 永远是 0。**

### 数据包

```
AA 55 | DevID(0x60) | CMD | LEN | DATA... | CS
```

- **CS = (DevID + CMD + LEN + DATA各字节) & 0xFF** —— 从 **DevID** 起算，**不含 `AA 55`**
- **两种模式数据顺序不同**：
  - 模式 0 全数据（LEN=18）：`AccX,AccY,AccZ, GyroX,GyroY,GyroZ, Pitch,Roll,Yaw`
  - 模式 1 仅姿态（LEN=6）：**`Yaw,Pitch,Roll`** ← Yaw 在第一位
- 姿态角均为 **×100 整数**；Pitch/Roll 是 `int16`，**Yaw 是 `uint16`**
- 本工程用**模式 0**（只有它带原始角速度 GyroZ）
- 开机发：`设全数据模式` `AA 55 60 0B 01 00 6C` → `启动上报` `AA 55 60 0A 01 01 6C`
- CMD 全集只有 `0x01/0x0A/0x0B/0x10/0x12/0x14/0xF0`，**没有任何频率设置** ⇒ 100 Hz 改不了

## 六、板间协议

### MaixCam2 → MSPM0（视觉，每帧）

```
AA 55 | STATUS | ERR_X_LO | ERR_X_HI | CHECKSUM        共 6 字节
```

| 字节 | 含义 |
|---|---|
| 0-1 | 帧头 `AA 55` |
| 2 | `STATUS`：1 = 检测到靶纸，0 = 未检测到 |
| 3-4 | `ERR_X`：**int16 小端有符号**，靶心 − 激光点（像素） |
| 5 | `CHECKSUM` = **前 5 字节之和** & 0xFF ← **含帧头** |

⚠️ 与陀螺协议相反：**这个校验包含帧头**。
**符号已确认**（2026-10-04 实测）：`err_x` 为正 = 靶心在激光点右侧，控制端 `w += AIM_GAIN_RATE × err_x` **直接相加、不取反**。

### MaixCam2 → 底盘（数字 N）

```
AA 55 | 'N'(0x4E) | DIGIT | CHECKSUM                  共 5 字节
```

- `DIGIT`：1~4 = 识别到的数字；**0 = 没认出来**
- `CHECKSUM` = 前 4 字节之和 & 0xFF
- 确认后**重复发 3 秒**（20 Hz，60 次），**不需要反向 ACK**

## 七、时钟

```
SYSOSC (片内 RC, 32 MHz)                    HFXT (PA5/PA6, 40 MHz)
   ├── MCLK  32 MHz                            └── HFCLK 40 MHz → (无人使用)
   │     ├── CPU / 外设总线
   │     └── BUSCLK 32 MHz ── UART0/1/2/3（四个串口全用它）
   └── MFPCLK (未使用)
SYSPLL 已禁用        LFCLK/LFXT 未使用
```

**所有在干活的外设都跑片内 SYSOSC，一个外部晶振都没用** ⇒ 四个串口的波特率精度 = SYSOSC 精度。已实测：视觉那路 115200 上万帧零校验错。

## 八、调试串口输出（UART0，`empty.c` 的 printf）

```
S=3 | V=2830 vc=0 vo=0 vg=19 | G=1004 M=0 TO=200 ME=0 RB=6 | E=-13 Ef=-11 R=-35 |R|=42 | psi=118 Del=92 W=15
```

| 字段 | 含义 | 健康值 |
|---|---|---|
| `S` | 当前 `AIM_STAGE` | 确认板子跑的是哪一档 |
| `V` | 视觉帧数 | 不涨 = MaixCam 没发 / UART3 接线错 |
| `vc` / `vo` | 视觉校验失败 / FIFO 溢出 | 0 |
| `vg` | 本周期最大视觉帧间隔 (ms) | ~29，用来抓帧率抖动 |
| `G` | 陀螺帧数 | 不涨 = 陀螺没发 / UART2 接线错；正常 +100/秒 |
| `M` | 云台反馈帧数 | **0（已知 bug，见 BUGS.md #1）** |
| `TO` | 云台等待超时次数 | 随发送频率增长（= 每次发送都超时） |
| `ME` | 云台帧错误 | 0 |
| `RB` | 云台收到原始字节数 | **恒为 0 才是硬件问题；RB 在涨但 M=0 是协议问题** |
| `E` / `Ef` | 视觉误差原始 / 卡尔曼滤波后 (px) | 控制用的是 **Ef**，两者对比能看出滤波压掉多少抖动 |
| `R` | 当前偏航角速度 | ⚠️ **打印的是 ×10 的值**（`R=35` = 3.5°/s） |
| `\|R\|` | 本周期平均 \|角速度\| | 同样 ×10；标定 `GYRO_LSB_PER_DPS` 用 |
| `psi` | 车体偏航角 (°)，陀螺 Yaw 回绕累加 | 手推车转弯会跟着变 |
| `Del` | ∠BOA (°)，由 psi 算出的车在弧上位置 | 左弯 90°→180°→90° |
| `W` | 本拍发出的速度指令 (°/s) | 前馈 + 视觉的合成结果 |

**`printf` 是非阻塞的**（`debug_uart.c`）：它只把字符塞进一个 **256 字节环形缓冲**就返回（**微秒级**），真正的发送交给 UART0 的 TX 中断在后台一个字节一个字节搬。所以它**不会拖慢 1 ms 的主循环**；缓冲区满时**丢弃**多出来的字符（宁可丢字也不卡控制环）。

实际开销全部落在 TX 中断上：调试行约 110 字符 ≈ 960 位，115200 下占线 **≈ 9 ms/秒 = 0.8% CPU**，可以忽略。**调试完不是必须关**（`DEBUG_PRINT_ENABLE` 现在就是 1）；要关只是为省这点中断开销。

排查云台反馈时把 `empty.c` 的 `DEBUG_GIMBAL_SNOOP` 改成 1，每秒多打一行 `RX1:` 原始十六进制字节。
