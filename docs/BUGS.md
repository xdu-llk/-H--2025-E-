## #1 QD4310 云台的反馈报文收不到

**记录日期**：2026-09-20
**状态**：**未解决，暂时搁置**
**影响**：**不影响打靶**。控制环靠视觉闭环，不依赖电机反馈。丢失的只是
"电机是否报错 / 是否被失能"的健康检查，以及 300ms 无反馈重连逻辑。

### 症状

调试行长期是：

```
M=0   TO 持续增长（速率 = 发送频率）   ME=0   RB 有数
```

- `M=0`：一帧有效反馈都没解析出来
- `TO` 每发一条就 +1：**每次发送都超时**
- `RB` 在涨：**线上确实有字节**（所以不是"完全没有数据"）

### 已经排除的

| 项 | 结论 | 依据 |
|---|---|---|
| **我们的 UART1 收发通路** | ✅ **完好** | 自环测试（PA8↔PA9 短接）时，能正确收到并解析自己发的指令，`M` 和 `ME` 都会涨 |
| **ISR 名 / NVIC / 引脚 / 初始化** | ✅ 全部正确 | 逐项核对过生成代码和启动文件 |
| **电机 TX → PA9 的线** | ✅ 已确认接上 | RB 有数就是证据 |
| **解析器本身** | ✅ 能工作 | 自环时能凑出帧（否则 `M`/`ME` 不会动） |

### 收集到的关键数据

**自环时**（PA8↔PA9 短接）：
- `RB` 约 800/秒（我们发 1000 字节/秒，差值是被发送前的 flush 丢掉的）
- `RX1` 里能清楚看到自己的指令：`01 00 00 6b`（使能指令尾）、`07 xx xx xx`（角度步进）、`fb`（清错误指令码）
- `M`、`ME` 都在涨 → 解析正常

**接电机时**（且自环跳线**还插着**）：
- `RX1` 全是 `00` → 看起来 RX 线被拉低

⚠️ **注意**：最后那次"全是 00"的数据，是在**自环跳线没拔**的情况下取的。
跳线插着时 PA8、PA9、电机的 TX 是同一个电气节点，**我们的 TX 和电机的 TX 在
对顶**，波形是坏的。所以那次数据**不能作为"电机没发/发错"的证据**。

### 还没验证的假设

1. **等待窗口太窄**——曾经怀疑电机的回复比等待窗口慢，回复到达时状态已回 IDLE，
   字节被丢弃或被下一次发送前的 flush 冲掉，导致永远凑不满 10 字节。
   *部分验证*：把窗口放宽到覆盖整个周期后，`M` 确实开始涨了（但那是自环，不能算数）。
2. **帧格式假设有误**——10 字节、CRC 覆盖前 9 字节，这两条都是从手册推的，
   手册**没有明确写 CRC 覆盖范围**。
3. **电机根本没回**——电机的 UART 是否真的按手册"收到指令就回一帧"工作。
4. **波特率**——电机侧的 UART 波特率是否真是 115200（手册说是默认值，但可能被改过）。

### 下次继续查的步骤

1. **确保只接电机，拔掉自环跳线**（关键！上次的数据就是被这个污染的）
2. 看 `RX1` 里出现的是什么：
   - 有规律的帧结构（比如每 10 字节一组，首字节是 `00`）→ 帧长对了，查 CRC
   - 杂乱的随机值 → 波特率不匹配
   - 全是 `00` → 线被拉低，查电机 TX 是否在拉低 / 是否和 GND 短
3. 用**上位机**确认电机的 UART 波特率和 ID（应该都是 `115200` / `000`）
4. 如果电机可能进了错误状态，先发 `0xFF 重启设备`
