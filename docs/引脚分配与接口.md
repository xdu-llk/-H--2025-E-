## 一、系统构成

```
        ┌──────────────┐  UART3 (PB2/PB3)   ┌─────────────────┐
        │  MaixCam2    │ ────────────────→  │                 │
        │  视觉        │   6字节帧 err_x    │                 │
        └──────┬───────┘                    │   MSPM0G3507    │
               │ UART1 (A30/A31)            │   天猛星主控     │
               │ 5字节帧 数字N               │                 │
               ↓                            │                 │
        ┌──────────────┐                    └────┬───────┬────┘
        │  底盘主控     │                         │       │
        │  循迹/电机    │                    UART1│       │UART2
        └──────────────┘                    (PA8/9)│      (PB17/18)
                                                   ↓       ↓
                                          ┌──────────┐  ┌──────────┐
                                          │ QD4310   │  │ 汇电籽-601│
                                          │ 云台电机  │  │ 陀螺仪   │
                                          └──────────┘  └──────────┘
```

**分工**：本板（MSPM0）只负责**视觉对准云台**；循迹、电机、定点停车由底盘主控负责。

### 注意

- ⚠️ **PA2 是 ROSC 脚**。原理图上标着「PA2/ROSC 精度很重要」——板子预留了提升
  SYSOSC 精度的精密电阻，但**我们把 PA2 分给了激光，ROSC 未启用**。
  若以后某路串口偶发误码，第一件可试的就是把激光挪脚、启用 ROSC。
- ⚠️ **HFXT 40MHz 晶振目前是"僵尸"**：它当初只为 CANCLK 服务，CAN 删除后就没人用了。
  但生成的代码里仍会开它，**开机要多等它起振 640µs，还白耗一份电**。
  要关的话在 SysConfig 里改三处（`useHFCLK_Manual=false`、`HFXT.enable=false`、
  `EXHFMUX` 回 Digital）。
- **CAN 已从 SysConfig 删除**，PA12/PA13 已释放。旧 CAN 驱动停在
  `gimbal_can.c.disabled`，不参与编译。

## 四、云台 QD4310

| 项 | 值 |
|---|---|
| 通信 | **UART**（不是 CAN），115200 8N1 |
| 设备 ID | **0**（`can.id = 000`，UART ID 与之相同） |
| 硬件 / 固件 | 4310_6.2.1 / Software 6.4.0 |
| 内部环 | 角度环 kp=**1200** ki=0 kd=0；速度环 kp=0.003 ki=0.390 |
| 限幅 | limit.current 1.65 A，limit.speed 1000 rpm |

### 接线（SH1.0-3Pin）

```
QD4310 T (TX) ──→ MSPM0 PA9      (UART1_RX)
QD4310 R (RX) ←── MSPM0 PA8      (UART1_TX)
QD4310 G     ──── MSPM0 GND
QD4310 XT30  ──── 24V 电源
```

### 数据包（手册 6.2.2 / 6.2.3）

**UART 包 = `[ID] + [CAN 包原样] + [CRC8]`**

| | 长度 | 布局 |
|---|---|---|
| **控制包** | 5 | `ID, 指令类型, 控制量(2, 小端), CRC8` |
| **反馈包** | 10 | `ID, 电机状态, 错误码, 电流(2), 转速(2), 角度(2), CRC8` |

- **CRC8**：多项式 `0x07`、初值 `0x00`、异或 `0x00`、不反转（标准 MSB-first CRC-8）
  ⚠️ 手册**没写覆盖范围**，本工程按"包内 CRC 之前的全部字节"处理
- **指令码**：`0x01`使能 `0x02`失能 `0x03`电流 `0x04`速度 `0x05`角度
  `0x06`低速 `0x07`**角度步进**（本项目用）`0xFB`清错误 `0xFE`置零 `0xFF`重启
- **角度编码**：`raw = θ / (2π) × 32767`

### ⚠️ 一发一收（最容易踩的坑）

手册 6.2.3 要求：**发一条 → 等反馈或超时 → 才能发下一条，严禁收发异步。**

所以**两条指令不能背靠背发**。本工程用状态机（`empty.c` 的 `gim_step`）每拍推进一步，
不依赖任何"猜多久够"的延时。

另外：**等待窗口必须覆盖整个发送周期**（`GIMBAL_RX_TIMEOUT_TICKS == SEND_PERIOD_TICKS`），
否则会留出 IDLE 空档，落在里面的字节全丢，帧永远攒不齐。

## 五、陀螺仪 汇电籽-601

| 项 | 值 |
|---|---|
| 芯片 | ICM42688 |
| 通信 | UART，115200 8N1 |
| 设备 ID | `0x60` |
| 回报率 | **100 Hz** |
| 电平 | **3.3V**（直连，不用电平转换） |

### 接线

```
模块 V (5V)  ────  5V
模块 T (TX)  ────→ MSPM0 PB18   (UART2_RX)
模块 R (RX)  ←──── MSPM0 PB17   (UART2_TX)   ← 必须接！
模块 G       ────  GND
```

⚠️ **这是双向的**：模块默认不上报，是靠我们开机发两条指令叫醒的。
**PB17 那根不接的话，指令到不了，`G` 永远是 0。**

### 数据包

```
AA 55 | DevID(0x60) | CMD | LEN | DATA... | CS
```

- **CS = (DevID + CMD + LEN + DATA各字节) & 0xFF** —— 从 **DevID** 起算，**不含 `AA 55`**
- **两种模式的数据顺序不同**：
  - 模式 0 全数据（LEN=18）：`AccX,AccY,AccZ, GyroX,GyroY,GyroZ, Pitch,Roll,Yaw`
  - 模式 1 仅姿态（LEN=6）：**`Yaw,Pitch,Roll`** ← Yaw 在第一位
- 姿态角均为 **×100 的整数**；Pitch/Roll 是 `int16`，**Yaw 是 `uint16`**
- 速率环用**模式 0**（只有它带原始角速度）
- 开机发：`设全数据模式` `AA 55 60 0B 01 00 6C` → `启动上报` `AA 55 60 0A 01 01 6C`

## 六、板间通信协议

### MaixCam2 → MSPM0（视觉，每帧）

```
AA 55 | STATUS | ERR_X_LO | ERR_X_HI | CHECKSUM      共 6 字节
```

| 字节 | 含义 |
|---|---|
| 0-1 | 帧头 `AA 55` |
| 2 | `STATUS`：1 = 检测到靶纸，0 = 未检测到 |
| 3-4 | `ERR_X`：**int16 小端有符号**，靶心 − 激光点（像素） |
| 5 | `CHECKSUM` = **前 5 字节之和** & 0xFF ← **含帧头** |

⚠️ 与陀螺那个协议相反：**这个校验包含帧头**。

### MaixCam2 → 底盘（数字 N，只发一次）

```
AA 55 | 'N'(0x4E) | DIGIT | CHECKSUM                共 5 字节
```

- `DIGIT`：1~4 = 识别到的数字；**0 = 没认出来**
- `CHECKSUM` = 前 4 字节之和 & 0xFF
- 确认后**重复发 3 秒**（20Hz，60 次），不需要反向 ACK

## 七、时钟分配

```
SYSOSC (片内 RC, 32 MHz)              HFXT (外部晶振 PA5/PA6, 40 MHz)
   │                                       │
   ├── MCLK ─────── 32 MHz                 └── HFCLK ── 40 MHz ─→ (无人使用)
   │      ├── CPU / 外设总线
   │      └── BUSCLK ── 32 MHz
   │             ├── UART0/1/2/3  (四个串口全用它)
   │
   └── MFPCLK ───── (未使用)

SYSPLL ──── 已禁用        LFCLK/LFXT ──── 未使用
```

**所有在干活的外设都跑在片内 SYSOSC 上，一个外部晶振都没用。**

⇒ **四个串口的波特率精度 = SYSOSC 的精度**。已实测：视觉那路 115200 跑了上万帧零校验错。

## 九、调试串口输出格式

```
V=393 vc=0 vo=0 vg=29 | G=1004 M=0 TO=200 ME=0 RB=6 | E=-13 R=-35 |R|=42
```

| 字段 | 含义 | 健康值 |
|---|---|---|
| `V` | 视觉帧数 | +35/秒 |
| `vc` | 视觉校验失败 | 0 |
| `vo` | 视觉 FIFO 溢出 | 0 |
| `vg` | 视觉最大帧间隔(ms) | 28~29 |
| `G` | 陀螺帧数 | +100/秒 |
| `M` | 云台反馈帧数 | **0（已知 bug，见 BUGS.md）** |
| `TO` | 云台等待超时次数 | 随发送频率增长 |
| `ME` | 云台帧错误 | 0 |
| `RB` | 云台原始字节数 | 0 |
| `E` | 视觉误差(像素) | 稳定后接近 0 |
| `R` | 偏航角速度(°/s) | 静止接近 0 |
| `\|R\|` | 本秒内的平均绝对角速度 | 静止接近 0 |
