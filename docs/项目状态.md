## 一、这是什么

2025 电赛 E 题「简易自行瞄准装置」的**实验室招新改编版**。
本工程只做**云台以上部分**（视觉 + 云台瞄准），底盘循迹由另一块主控负责。

**三块板**：MSPM0G3507（主控）· MaixCam2（视觉）· 底盘主控（不管）

## 二、控制架构：四层

```
【视觉环】  err_x(像素) → 累加 → 目标航向 yaw_ref      很慢 ~0.2 Hz
     ↓                                                  ← 我们写
【航向环】  e = yaw_ref − yaw_total(IMU) → w → Δθ       1~2 Hz
     ↓  5 字节 UART (0x07 角度步进)
【电机角度环】 编码器反馈，kp=1200                      QD4310 内部
【电机速度环】 编码器反馈，kp=0.003/ki=0.1              QD4310 内部
```

**⚠️ 为什么不用纯速率环**：速率环要让 ω=0，带宽必须高，100 Hz 陀螺 + 10 ms 延迟撑不住
（实测 K=0.15 就震）。**角度环只需"守住方向"，带宽低，延迟不致命。**

**⚠️ 视觉项是纯积分（`yaw_ref = K∫err_x dt`），但它的**变化率**正比于误差 ——
这就是"接近减速"的来源，也是不过冲的原因。**

## 四、关键结论（踩过的坑 / 为什么这样）

| # | 结论 |
|---|---|
| 1 | **模块的 Yaw 和 GyroZ 符号相反** —— 实测：手转时 gZ 持续为正而 yaw100 持续下跌。不翻 `YAW_SIGN` 的话航向环就是正反馈，云台一直转 |
| 2 | **自稳的病根在内环（速度环 ki）**，不在外环 —— 降 ki 0.390→0.1 后立刻好转 |
| 3 | **纯速率环走不通** —— 实测 K=0.3 震 / 0.15 轻微震 / 0 不震 |
| 4 | **卡尔曼比一阶低通好得多** —— 匀速目标下卡尔曼滞后 **0 px**，低通 α=0.5 是 6 px（1.27°，1.25m 处 2.8cm） |
| 5 | **`AIM_MAX_RATE_RAD_S` 必须 ≥ 视觉环最大推速**，否则 `yaw_ref` 跑在前面 → 大误差过冲 |
| 6 | **死区防的是 `yaw_ref` 累加器**（不是 `g_yaw_i`，那个没开） |
| 7 | **陀螺模块内部已做融合滤波**（Yaw 那条路）。GyroZ 是"原始数据"，但我们只用它做阻尼，增益小，无需再滤 |
| 8 | **云台无限位**（可 360° 连续转）—— 找靶扫描不受角度限制 |
| 9 | 天猛星供电：排针 `5V` **直连 USB VBUS**，可用外部 5V 灌。**必须共地**（走 QD4310 的 SH1.0 G 线，或直连 24V 负极） |
| 10 | **模块的 Yaw 不慢漂**（实测）—— 6 轴 IMU 常见的漂移在这个模块上可忽略 |

## 五、MaixCam2 侧（`rectangle/`）

**⚠️ 2026-09-28 大改：`no_canny.py` 取代 `camera_display.py`**

`camera_display.py`（带 Canny 那版）帧率不够，已删除（见 `efec787`，git 里可回退）。
算法与串口全部搬进 `no_canny.py`，`main.py` 是入口。

**上电两阶段**（回到 `d357f02` 的做法）

```
① 启动 → 相机切 416×416
② 跑 YOLOv5 数字模型, 最多 10 s; 连续 5 帧同一个数字才算认出
③ 把 N 发给底盘 (重复 3 s, 不等 ACK) → 相机切回 416×260
④ 矩形识别瞄准, 跑到底
```

| 要点 | 说明 |
|---|---|
| **为什么要切分辨率** | 数字模型要 416×416 正方形；而矩形识别那套阈值（`MIN_AREA` 等）**全按 416×260 标定**，换分辨率就全作废 |
| **切回后不重锁曝光** | 实测 ISP 不会重置。`init_camera()` 只在开机锁一次（`EXPOSURE_US = 5000`） |
| **标签陷阱** | 模型 labels 是 `["3","1","2","4"]`，必须 `labels[class_id]` 反查，**别写 `class_id+1`** —— 那会把 3 当成 1、4 当成 2，停错点位 |
| **底盘协议** | `AA 55 'N' <digit> <sum>`（5 字节）。**没有 ACK** —— 重复发 3 秒，发几十遍总有一遍能到，两边都只做单向 |
| **`digit = 0`** | 10 s 内没认出来，发 0 让底盘知道 |
| **两路串口** | UART4 `A21/A22` → 云台（每帧 `err_x`）；UART1 `A30/A31` → 底盘（只在认出时发 N）|

**矩形识别相对旧版的两处改动**

| 项 | 改动 |
|---|---|
| `USE_CANNY` | → `False`（"no_canny" 的由来，省掉一道 Canny）|
| `MAX_INNER_OUTER_RATIO` | **新增 0.85**（`3376bbc`）—— 旧版只有下限 0.68，挡不住"框太细"的干扰（显示器边框、画框），那类东西的比值接近 1 |

**内外框比值的物理值**（换胶带宽度要重算）

```
真靶纸: A4 外框 297×210 − 18mm 胶带 = 内孔 261×174   →  0.728
框宽 t:  t=18mm 0.728   t=12mm 0.814   t=10mm 0.844   t=5mm 0.920
⇒ 下限 0.68 / 上限 0.85 相当于只接受框宽 10 ~ 21.5mm
```

**⚠️ MaixPy UART API（官方文档确认）**
```python
serial.read()                     # = read(-1,0)，有数据立刻返回，没有返回 b''
serial.read(len=-1, timeout=5)    # 阻塞最多 5ms
serial.write(bytes)               # 发字节流
serial.write_str(str)             # 发字符串
# ⚠️ 没有 any()！
# ⚠️ 用了 set_received_callback 就不能再 read()
```
