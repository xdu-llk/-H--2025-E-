### 2.1 云台环结构

`application/gimbal/gimbal.c` 里 yaw 电机的配置：

```c
.controller_param_init_config = {
    .angle_PID = {
        .Kp = 0.3,   .Ki = 0.8,  .Kd = 0.005,
        .IntegralLimit = 20,  .MaxOut = 20,
        .CoefA = 15.0f, .CoefB = 1.0f,
        .Improve = PID_Trapezoid_Intergral | PID_Integral_Limit
                 | PID_Derivative_On_Measurement | PID_ChangingIntegrationRate,
    },
    .speed_PID = {
        .Kp = 1200,  .Ki = 0,    .Kd = 3,
        .IntegralLimit = 16000,  .MaxOut = 16000,
        .Output_LPF_RC = 0.001,                 // ← 输出低通 ≈160 Hz
        .Improve = ... | PID_OutputFilter,
    },
    // ★ 两个反馈指针都指向 IMU
    .other_angle_feedback_ptr = &gimba_IMU_data->YawTotalAngle,   // 姿态角
    .other_speed_feedback_ptr = &gimba_IMU_data->Gyro[2],         // 角速度
    .speed_feedforward_ptr    = &yaw_speed_feedforward,           // 另一个东西
},
.controller_setting_init_config = {
    .angle_feedback_source = OTHER_FEED,
    .speed_feedback_source = OTHER_FEED,
    .close_loop_type = SPEED_LOOP | ANGLE_LOOP,
    .feedforward_flag = SPEED_FEEDFORWARD | CURRENT_FEEDFORWARD,
},
```

**要点：**

1. **角度环和速度环的反馈全部来自 IMU，完全不用电机编码器。**
   源码注释原话："后续考虑只保留IMU控制, 不再需要电机的反馈"。
2. **陀螺是【速度环的反馈】，不是前馈。** 速度环的目标就是"让云台的惯性角速度为 0"。
3. **`speed_feedforward_ptr` 是另一样东西** —— 它接的是参考轨迹的导数
   （`yaw_speed_feedforward = DEGREE_2_RAD * (yaw - yaw_last_ref) * 500.0f`，
   限幅 ±10）。**反馈和前馈是两个独立的通道，不能混为一谈。**

### 2.2 陀螺链

`modules/BMI088/bmi088.c` 的初始化表：

```c
{BMI088_ACC_CONF,      BMI088_ACC_NORMAL | BMI088_ACC_800_HZ | ..., ...}
{BMI088_GYRO_BANDWIDTH, BMI088_GYRO_1000_116_HZ | ..., ...}
```

`modules/BMI088/bmi088_regNdef.h`：

```c
#define BMI088_ACC_800_HZ          (0xB << BMI088_ACC_ODR_SHFITS)
#define BMI088_GYRO_1000_116_HZ    0x02      // ODR 1000 Hz，芯片内置 116 Hz 低通
```

`modules/imu/ins_task.c`：

```c
IMU_QuaternionEKF_Init(init_quaternion, 10, 0.001, 1000000, 1, 0);
INS.AccelLPF = 0.0085;      // 只有加速度加了一阶低通
IMU_QuaternionEKF_Update(INS.Gyro[X], INS.Gyro[Y], INS.Gyro[Z], ...);
```

**要点：**

1. **陀螺 ODR = 1000 Hz**，即采样延迟 ≈ **1 ms**
2. **低通在芯片硬件里**（116 Hz），不是软件加的 —— 所以不额外吃相位
3. **陀螺原始值直接进 EKF**，没有软件滤波
4. 数据就绪靠**中断 + DMA** 驱动，解算任务跟着中断走
5. ⚠️ 它还有 **`heat_pid` / `heat_pwm`** —— BMI088 有**加热恒温**，靠 PID 维持温度。
   这是为什么这类模块摸起来是热的。

### 2.3 三条值得学的

| # | 做法 | 我们的差距 |
|---|---|---|
| 1 | 陀螺数据率 **1000 Hz** | 我们 **100 Hz**，差 10 倍 ⚠️ |
| 2 | 滤波放在**硬件**（芯片 LPF） | 我们**零滤波** |
| 3 | 速率环是**真 PID**（Kp/Kd/输出滤波都可调） | 我们增益**被 dt 锁死 = 1.0** |

## 三、我们的结构

```
MaixCam2 ──err_x──→ MSPM0 ──Δθ 增量(0x07)──→ QD4310
                      ↑                          │
                      │                    内部: 角度环 kp=1200
                      │                          速度环 kp=0.003/ki=0.390
                      │                          （反馈 = 电机编码器）
                      └── 陀螺 ω (UART2, 100 Hz) ──┘
```

**根本差异：QD4310 内部闭环用的是【编码器】（相对角度），不是 IMU。**

所以车体转动时，电机的角度环会老老实实保持"相对车体的角度不变" →
云台跟着车一起转 → 激光偏。**这正是速率环存在的理由。**

而我们的速率环，写成了：

```c
dtheta += GYRO_RATE_SIGN * GYRO_RATE_K * (yaw_rate_dps * DEG2RAD) * SEND_PERIOD_SEC;
```

## 四、为什么"前馈"这个名字是错的

原来的写法（`GYRO_RATE_K` 相当于 1.0）：

```c
dtheta += GYRO_FF_SIGN * (ω * DEG2RAD) * SEND_PERIOD_SEC;
```

**关键认识：`SEND_PERIOD_SEC` 乘了又除，增益被锁死。**

```
我们的输出 = Δθ (每拍转角)
云台响应   ω_out = Δθ / dt           ← 内环快，近似是速度源

速率项折算成速率 = (−ω · dt) / dt = −ω      增益 = 1.0
```

**这不是"叠加一个补偿量"，这是一个增益恰好为 1.0 的速率反馈环。**

叫它"前馈"的后果是：**从来没按闭环去设计它** —— 没有增益、没有滤波、没有稳定性分析。
江南那边 `speed_PID` 是个正儿八经的 PID，`Kp` 是要整定的。

> 反馈（feedback）= 用测到的输出去修正输入 = **闭环**
> 前馈（feedforward）= 用已知的参考轨迹提前补偿 = **开环**
>
> 我们做的是前者。

## 五、增益上限推导（本文档的核心）

### 5.1 临界增益

速率反馈环，回路里有一个纯延迟 τ：

```
闭环特征方程:   1 + K · e^(−sτ) = 0

K < 1  →  极点全在左半平面          稳定
K = 1  →  e^(−sτ) = −1 → s = jπ/τ  虚轴上一对极点，临界振荡
K > 1  →  极点跑到右半平面          发散
```

**所以增益的硬上限就是 1.0** —— 而我们的代码恰好卡在 1.0。

### 5.2 临界频率

τ 就是陀螺的采样延迟：

```
陀螺 100 Hz 上报  →  τ ≈ 10 ms
临界频率 f = 1/(2τ) = 1/(2 × 0.01) = 50 Hz
```

**50 Hz 的持续振荡 = 你听到的"剧烈抖动"。**

实际还有云台内环滞后 + 陀螺自身滤波滞后 → **等效延迟 > 10 ms** →
极点进入右半平面 → 振幅增长 → 最后被 `AIM_MAX_RATE_RAD_S` 夹住 →
**持续剧烈震荡**。

⚠️ **这条链解释了你观察到的全部现象**：主控重启 → 陀螺开始上报 →
速率环投入 → 立刻自激。

### 5.3 为什么江南没有这个问题

```
江南:  τ ≈ 1 ms   →  K 可以到 10 (量级)
我们:  τ ≈ 10 ms  →  K 必须 < 1
```

**十倍的数据率，换来十倍的可用增益。** 这就是 1000 Hz 与 100 Hz 的实际差别。

### 5.4 推论：我们的自稳能力有天花板

稳态下（车体以 ω_body 匀速转）：

```
ω_gimbal = ω_body  −  K · ω_gimbal
        ⇒ ω_gimbal = ω_body / (1 + K)
```

| K | 车体扰动残余 |
|---|---|
| 0（无速率环） | 100% |
| 0.3 | 77% |
| 0.9 | 53% |
| **1.0（上限）** | **50%** |

**即使用到极限，也只能把车体转动的影响减半。** 剩下的一半要靠视觉环去追。

**这不是调参能突破的，是 100 Hz 数据率决定的物理限制。**
想真正做好自稳，必须提高陀螺上报率。

## 六、参数与调法

全部在 [`empty.c`](../empty.c) 顶部「陀螺速率环」一段。

| 参数 | 当前值 | 说明 |
|---|---|---|
| `GYRO_RATE_AXIS` | `2u` | 用哪个轴。Z 轴竖直朝上 → 2 |
| **`GYRO_RATE_K`** | **`0.3f`** | **速率环增益，必须 < 1.0** |
| `GYRO_RATE_SIGN` | `-1.0f` | 符号（已实测确认） |
| `GYRO_LPF_ALPHA` | `0.8f` | 一阶低通，≈26 Hz。**1.0 = 关闭** |

### K 是什么

速率环增益 —— 陀螺测到云台在转，**用多大力气把它按回去**。

| K | 车体转动残余 | 抵消 |
|---|---|---|
| 0 | 100% | 0 |
| 0.3 | 77% | 23% |
| 0.5 | 67% | 33% |
| 1.0（上限） | 50% | 50% |

```
ω_残余 = ω_车体 / (1 + K)
```

**为什么必须 < 1.0**：陀螺 **10 ms 之后**才告诉我们"云台转了 ω"。
K=1 时命令量恰好等于它转过的那段角度 → 指令到达时，推的方向和它运动的方向**一致**
→ 越推越猛（就是那个剧烈震荡）。K 越小推得越轻，延迟就翻不起浪。

### 调 `GYRO_RATE_K`

```
1. 0.3 起烧一板  →  应该能明显感到云台变稳，且不震
2. 每次 +0.1     →  加到开始出现高频抖动就往回退一步
3. 在"阻尼感"和"抖动"之间取平衡
```

⚠️ 提高 K 会**同时压低视觉环的有效增益**（速率环会抵抗被命令的运动）。
若发现追靶变迟钝，把 `AIM_GAIN_RATE` 相应往上补一点。

### 调 `GYRO_LPF_ALPHA`

```
f_c = −ln(1 − alpha) / (2π · T_gyro),   T_gyro = 10 ms

alpha = 1.00 → 关闭滤波
alpha = 0.80 → f_c ≈ 26 Hz   （默认）
alpha = 0.60 → f_c ≈ 15 Hz
```

⚠️ **滤波会产生相位滞后，而滞后正是自激的根源 —— 别做重，会火上浇油。**
顺序：先调 `GYRO_RATE_K`，压不住噪声再动这里。

⚠️ 滤波**每个陀螺帧只跑一次**（不是每个控制拍）。陀螺 100 Hz、主循环 1 kHz，
按拍跑的话同一个值会被反复滤波，等效截止频率变成 10 倍。

## 六之二、调参实测流程

**不需要改代码** —— 调试行的 `R` 字段就是判据。

`R` 是陀螺读到的**云台惯性角速度**（陀螺装在云台上），正是速率环要压的量。

### 做法

```
1. 云台静止上电，等 R 稳下来 —— 记下静止时的 |R|（应接近 0）
2. 用手【匀速】转车身（约 1 秒转 90°），盯 R 的读数
3. K 从 0.3 起，每次 +0.1 重烧，重复 1~2
4. 出现高频抖动 → 退回上一个 K
```

⚠️ 步骤 2 必须**匀速**。猛甩会触发 `AIM_MAX_RATE_RAD_S` 限幅，读数就没法横向比较了。

⚠️ 每次手转的速度尽量一致，否则不同 K 之间没得比。

### 记录表

| K | 静止 \|R\| | 手转车身时 R | 有无抖动 | 结论 |
|---|---|---|---|---|
| **0.3** | | | | |
| 0.4 | | | | |
| 0.5 | | | | |
| 0.6 | | | | |
| 0.7 | | | | |
| 0.8 | | | | |
| 0.9 | | | | |

### 怎么读结果

理论上 K 每加 0.1，`R` 应按 `1/(1+K)` 下降：

| K | 理论残余 |
|---|---|
| 0 | 100% |
| 0.3 | 77% |
| 0.5 | 67% |
| 0.8 | 56% |
| 1.0 | 50% |

**判定：**

| 现象 | 结论 |
|---|---|
| `R` 随 K 稳步下降，静止时 `\|R\|` 仍接近 0 | ✅ 正常，继续加 |
| **静止时 `\|R\|` 开始跳 / 云台有高频抖** | 🔴 **过冲了，退回上一个 K** |
| `R` 不降反升 | 🔴 符号反了 → 检查 `GYRO_RATE_SIGN` |
| `R` 完全不变 | 🔴 速率环没生效 → 查 `rate_valid` / 陀螺是否掉线 |

### 量化"自稳够不够用"

调完之后，用 **1.25 m 处的实际偏移**验收：

```
残余角速度 R (°/s) × 视觉环时间常数 τ (≈100 ms)
    = 视觉来不及补掉的稳态角度误差
    × 1.25 m → 实际偏移 (mm)
```

例：K=0.5、车体 35°/s → 残余 ≈ 23°/s；视觉环追斜坡的稳态误差 = 23 × 0.1 = 2.3°，
在 1.25 m 处约 **50 mm**。**对着 5 cm 指标卡一下就知道够不够。**

### ✅ 已确认：上报率提高不了

查过 `D:\monitor_uart\hdz_icm42688\汇电籽-601通信协议说明书.pdf`（2026.06.22 版），
**协议里没有任何频率/带宽设置指令**：

| CMD | 功能 |
|---|---|
| `0x01` | 上报数据（18 / 6 字节） |
| `0x0A` | 启动 / 停止上报 |
| `0x0B` | 设置输出模式 |
| `0x10` | 触发重新校准 |
| `0x12` | 软复位 MCU |
| `0x14` | Yaw 单圈比例校准 |
| `0xF0` | 通用应答 (ACK) |

**100 Hz 是模块固件写死的。** 手册说模式 1"适合高刷新率"，但它没有原始陀螺，
只能靠 Yaw 差分求角速度（滞后 + 噪声放大），**对速率环没用**。

| 延迟 | ≈10 ms | **≈1 ms** |
| 速率环增益上限 | **1.0** | **≈10** |

**参考实现在磁盘上**（不在工作区）：
`…/底盘代码/SeekFree_MSPM0G3507_Opensource_Library/project/code/ICM_42688.c`

+ 重做零偏标定。

**决策依据：先走 A，量化自稳精度。够指标就收工，明显超标再做 B。**

```diff

+ #define GYRO_RATE_AXIS          2u
```
