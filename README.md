## 1. 硬件

**三块板**：MSPM0G3507（**立创·天猛星**）· MaixCam2（视觉）· 底盘主控

> ⚠️ **不是 TI LaunchPad**。`LP-MSPM0G3507` 排针布局与本板完全不同，套用会得到"能编译但引脚错位"的固件。只从 SDK 取器件特性，引脚从 SysConfig pinmux 取。

| **UART1** 云台 | PA8 (TX) / PA9 (RX) | PINCM19 / 20 | QD4310 的 R / T | 115200 8N1 |
| **UART2** 陀螺 | PB17 (TX) / PB18 (RX) | PINCM43 / 44 | 汇电籽-601 的 R / T | 115200 8N1 |
| **UART3** 视觉 | PB2 (TX) / PB3 (RX) | PINCM15 / 16 | MaixCam2 的 A22 / A21 | 115200 8N1 |
| **激光** | PA2 | PINCM7 | 激光笔 MOS 管栅极 | 输出，**高=开**，上电 Cleared + 内部下拉 |
| 外部晶振 | PA5 / PA6 | PINCM10 / 11 | 40 MHz 晶振 | **僵尸，无人使用** |
| SWD | PA19 / PA20 | — | DAPLink | |

**MaixCam2**：视觉串口 A21(TX)/A22(RX) = `UART4` ↔ MSPM0 PB3/PB2 · 底盘串口 A30(TX)/A31(RX) = `UART1`（只发不收）· 设备名规律 **UARTn → `/dev/ttySn`**

```
QD4310  T(TX) → PA9   R(RX) ← PA8   G → GND   XT30 → 24V
陀螺    T(TX) → PB18  R(RX) ← PB17 ← 必须接！  V → 5V  G → GND（3.3V 电平直连）
MaixCam A21(TX) → PB3  A22(RX) ← PB2
```

- ⚠️ **PA2 是 ROSC 脚**。原理图标注「PA2/ROSC 精度很重要」，板子预留了提升 SYSOSC 精度的精密电阻，但**我们把 PA2 分给了激光，ROSC 未启用**。若以后某路串口偶发误码，第一件可试的就是启用 ROSC（把激光挪脚）。
- ⚠️ **HFXT 40 MHz 晶振是"僵尸"**：当初只为 CANCLK 服务，CAN 删除后没人用，但生成的代码仍会开它，**开机多等 640 µs 起振还白耗电**。要关就改 SysConfig 三处：`useHFCLK_Manual=false`、`HFXT.enable=false`、`EXHFMUX` 回 Digital。
- **CAN 已删除**，PA12/PA13 释放；旧驱动在 `gimbal_can.c.disabled`，不编译。
- **时钟**：`SYSOSC 32 MHz → MCLK → BUSCLK` 供 UART0/1/2/3；SYSPLL 禁用、LFXT 未用、HFCLK 无人用。⇒ **四个串口波特率精度 = SYSOSC 精度**。已实测视觉那路 115200 上万帧零校验错。

## 2. 控制结构：云台**开环**，没有云台角度反馈

```
速度指令(0x04, rad/s) = 几何前馈 + 视觉 P        两路同量纲，直接相加
```

- **几何前馈**：陀螺测**车体**偏航 ψ → 反推车在椭圆弧上的位置 → 靶方位角变化率 `guidance_ff()`。**QD4310 速度是"转子相对定子"**，定子固定在车架上 ⇒ 车头自己转的那份必须由前馈扣掉，否则云台跟着车头跑。
- **视觉 P**：`AIM_GAIN_RATE × err_x`（经 2 态卡尔曼），只管静态残差。
- **没有速率自稳环**：陀螺装**车体**上，不测云台。旧文档的 `GYRO_RATE_K` / 速率环 / 航向环**全部已废弃**，代码里不存在。
- **开机序列**：`清错误(0xFB) → 使能(0x01) → 回零(0x05→0°)`，等 500 ms 再放行瞄准（否则第一条 `0x04` 把回零的位置环半路切走）。**进弯**用 `0x05` 绝对角定位 300 ms（`SYNC_MAX_TICKS=60`），之后交棒给前馈+视觉。
- **发送**：收到新视觉帧立刻发（事件驱动，延迟 0~1 ms），`SEND_PERIOD_TICKS=5 ms` 只在断流时兜底。⚠️ 速度模式补帧**不能发 `0x00`**（那是"保持上一拍速度"），必须显式发 0 速度。
- **几何常量**（`guidance.h`）：`GEO_R_PATH=0.5`（车到半圆圆心）· `GEO_R_TGT=0.75`（靶到圆心）· `GEO_DELTA0_LEFT=-90°` / `RIGHT=+90°`。目标量是 **dθ/dt**，与坐标系无关，两半圆通用。

## 4. MaixCam2 侧（`rectangle/`，入口 `main.py` → `no_canny.py`）

```
① 相机切 416×416 → YOLOv5 数字模型（最多 10 s）→ 连续多帧同一数字才算认出
② 把 N 发给底盘（重复 3 s，不等 ACK）→ 相机切回 416×260
③ 矩形识别瞄准，每帧把 err_x 发给云台，跑到底
```

| 要点 | 说明 |
|---|---|
| **为什么要切分辨率** | 数字模型要 416×416 方形；矩形那套阈值**全按 416×260 标定**，换分辨率就作废 |
| **切回后不重锁曝光** | ISP 不会重置，`EXPOSURE_US = 5000` 只在开机锁一次 |
| **标签陷阱** | 模型 `labels = ["3","1","2","4"]`，必须 `labels[class_id]` 反查，**别写 `class_id+1`**（会把 3 当 1，停错点位） |
| **MaixPy UART API** | `read()` 有数据立刻返回、`read(len, timeout)`、`write()`/`write_str()`；**没有 `any()`**；用了 `set_received_callback` 就不能再 `read()` |

**矩形识别常量**：`THRESH_MODE="fixed"` / `FIXED_THRESHOLD=100` · `USE_CANNY=False` · `MIN_AREA=1300`、`MIN_PERIMETER=49`、`MIN_SIDE_PX=16` · 内外框比 `0.68~0.82` · `MIN_RING_OVERLAP=0.95`、`RING_GROW_SIZE=7` · `PROFILE=False`

## 5. 协议

### 云台 QD4310（UART，115200 8N1，设备 ID **0**，固件 Software 6.4.0）

**UART 包 = `[ID] + [CAN 包原样] + [CRC8]`** · 控制包 **5** 字节 `ID, 指令, 控制量(2 小端), CRC8` · 反馈包 **10** 字节 `ID, 电机状态, 错误码, 电流(2), 转速(2), 角度(2), CRC8`

- **CRC8**：多项式 `0x07`、初值 `0x00`、异或 `0x00`、不反转（标准 MSB-first CRC-8）。⚠️ 手册**没写覆盖范围**，本工程按"包内 CRC 之前的全部字节"（控制 4 / 反馈 9）处理。
- **指令码**：`0x01`使能 `0x02`失能 `0x03`电流 `0x04`速度 `0x05`角度 `0x06`低速 `0x07`角度步进 `0xFB`清错误 `0xFE`置零 `0xFF`重启
- **控制量编码**（⚠️ 两个角度指令满量程不同）：

| 指令 | 类型 | 换算 | 满量程 |
|---|---|---|---|
| `0x05` 角度控制 | **uint16** | `raw = θ/(2π) × 65535` | 65535 |
| `0x07` 角度步进 | int16 | `raw = Δθ/(2π) × 32767` | ±32767 |
| `0x04` 速度 | int16 | `raw = rpm/1000 × 32767` | ±32767 |
| `0x03` 电流 | int16 | `raw = A/10 × 32767` | ±32767 |

- **⚠️ 一发一收（手册 6.2.3）**：发一条 → 等反馈或超时 → 才能发下一条，**严禁收发异步**。所以**两条指令不能背靠背发**（`gimbal_clear_error(); gimbal_enable();` 第二条必然被"还在等反馈"挡掉，**且不报任何错**）。本工程用状态机（`empty.c` 的 `gim_step`）每拍推进一步。等待窗口必须**覆盖整个发送周期**，否则留 IDLE 空档、字节全丢（表现：`RB` 在涨但 `M=ME=0`）。
- **内部环**（厂家上位机改、存在电机里，**不在代码里**；改完必须点「储存」否则断电回原值）：角度环 `kp=150 ki=0 kd=0`；速度环 `kp=0.030 ki=0.39 kd=0`（2026-10-04 上位机读出，**当前实跑值**；0.39 是调好的好参数，**别再往下压**）。**两个环各管一种模式**：速度环 ← 平时 `0x04` 瞄准；角度环 ← 进弯 `0x05` 一次定位（已实测没问题）。限幅 current 1.65 A / speed 1000 rpm。

### 陀螺 汇电籽-601（ICM42688，UART 115200 8N1，3.3V 直连）

帧 `AA 55 | DevID(0x60) | CMD | LEN | DATA... | CS`，**CS = (DevID + CMD + LEN + DATA各字节) & 0xFF** —— 从 **DevID** 起算，**不含 `AA 55`**

- **两种模式数据顺序不同**：模式 0 全数据（LEN=18）`AccX,AccY,AccZ, GyroX,GyroY,GyroZ, Pitch,Roll,Yaw`；模式 1 仅姿态（LEN=6）**`Yaw,Pitch,Roll`**（Yaw 在第一位）
- 姿态角均 **×100 整数**；Pitch/Roll 是 `int16`，**Yaw 是 `uint16`**
- 本工程用**模式 0**（只有它带原始角速度 GyroZ）。开机发 `设全数据模式` `AA 55 60 0B 01 00 6C` → `启动上报` `AA 55 60 0A 01 01 6C`
- **回报率 100 Hz 是固件写死的**（CMD 只有 `0x01/0x0A/0x0B/0x10/0x12/0x14/0xF0`，没有任何频率设置）

### 板间

**MaixCam2 → MSPM0（视觉，每帧）** `AA 55 | STATUS | ERR_X_LO | ERR_X_HI | CHECKSUM` 共 6 字节
`STATUS` 1=检测到靶纸 0=未检测 · `ERR_X` **int16 小端有符号** = 靶心 − 激光点(px) · `CHECKSUM` = **前 5 字节之和** & 0xFF ← **含帧头**（与陀螺协议相反）。**符号已确认**：err_x 为正 = 靶心在激光点右侧，控制端直接相加不取反。

**MaixCam2 → 底盘（数字 N）** `AA 55 | 'N'(0x4E) | DIGIT | CHECKSUM` 共 5 字节
`DIGIT` 1~4；**0 = 没认出来** · `CHECKSUM` = 前 4 字节之和 & 0xFF · 确认后**重复发 3 秒**（20 Hz，60 次），**无 ACK**

## 6. 调试串口输出（UART0，`empty.c:614` 的 printf）

```
S=3 | V=2830 vc=0 vo=0 vg=19 | G=1004 M=0 TO=200 ME=0 RB=6 | E=-13 Ef=-11 R=-35 |R|=42 | psi=118 Del=92 W=15
```

| 字段 | 含义 | 健康值 |
|---|---|---|
| `S` | 当前 `AIM_STAGE` | 确认板子跑的是哪一档 |
| `V` / `G` | 视觉帧数 / 陀螺帧数 | 正常 +35/秒、+100/秒；不涨 = 没发或接线错 |
| `vc` / `vo` / `vg` | 视觉校验失败 / FIFO 溢出 / 最大帧间隔(ms) | 0 / 0 / ~29（抓帧率抖动） |
| `M` / `TO` / `ME` / `RB` | 云台反馈帧 / 等待超时 / 帧错误 / 收到原始字节 | `M=0`+`TO` 涨 = §7 #1。**`RB` 恒 0 才是硬件问题；`RB` 涨但 `M=0` 是协议问题** |
| `E` / `Ef` | 视觉误差原始 / 卡尔曼滤波后 (px) | 控制用 **Ef**；两者对比能看出滤波压掉多少抖动 |
| `R` / `absR` | 当前偏航角速度 / 本周期平均角速度绝对值 | ⚠️ **都打印 ×10 的值**（`R=35` = 3.5°/s）；`absR` 用来标定 `GYRO_LSB_PER_DPS` |
| `psi` / `Del` / `W` | 车体偏航角(°) / 车在弧上位置角(°) / 本拍速度指令(°/s) | 手推车转弯 `psi` 跟着变；左弯 `Del` 90°→180°→90°；`W` = 前馈+视觉合成 |

**`printf` 是非阻塞的**（`debug_uart.c`）：只把字符塞进 **256 字节环形缓冲**就返回（微秒级），发送交给 UART0 TX 中断在后台搬。**不会拖慢 1 ms 主循环**；缓冲满时**丢弃**多出来的字符（宁可丢字也不卡控制环）。实际开销约 **9 ms/秒 = 0.8% CPU**，可忽略。**调试完不是必须关**（`DEBUG_PRINT_ENABLE` 现在就是 1）。
排查云台反馈时把 `empty.c` 的 `DEBUG_GIMBAL_SNOOP` 改成 1，每秒多打一行 `RX1:` 原始十六进制字节。

## 7. 已知问题

### #1 QD4310 云台反馈报文收不到（2026-09-20 记录，**未解决，暂时搁置**）

**影响**：**不影响打靶**。控制环靠视觉闭环，不依赖电机反馈。丢的只是"电机是否报错/被失能"的健康检查，以及 300ms 无反馈重连逻辑。
**症状**：`M=0`（一帧都没解析出来）· `TO` 每发一条 +1（每次发送都超时）· `ME=0` · `RB` 在涨。
**已排除**：我们的 UART1 收发通路 ✅（自环 PA8↔PA9 短接时能正确收到并解析自己发的指令，`M`/`ME` 都涨）· ISR 名/NVIC/引脚/初始化 ✅ · 电机 TX→PA9 的线 ✅（`RB` 有数就是证据）· 解析器本身 ✅
⚠️ **关键污染**：那次"`RX1` 全是 `00`"的数据是在**自环跳线还插着**时取的 —— 跳线插着时 PA8、PA9、电机 TX 是**同一电气节点**，我们的 TX 和电机的 TX 在对顶，波形是坏的。**不能作为"电机没发"的证据。**
**未验证的假设**：① 等待窗口太窄（部分验证：放宽到覆盖整周期后 `M` 开始涨，但那是自环不算数）② 帧格式假设有误（10 字节、CRC 覆盖前 9 字节都是从手册推的，手册没写）③ 电机根本没回 ④ 波特率不是 115200

**下次继续查**：① **确保只接电机、拔掉自环跳线（关键！）** ② 看 `RX1` 原始字节：有规律帧结构（每 10 字节一组、首字节 `00`）→ 查 CRC；杂乱随机 → 波特率不匹配；全是 `00` → 线被拉低 ③ 用**上位机**确认电机 UART 波特率和 ID（应 `115200` / `000`）④ 若电机可能进了错误状态，先发 `0xFF 重启设备`

## 8. 踩过的坑（别再踩）

| 坑 | 内容 |
|---|---|
| **MSPM0 + SysConfig 的 NVIC 坑** | SysConfig **只生成外设级中断使能**（`DL_UART_Main_enableInterrupt`），**NVIC 那层不生成**，必须自己在 init 里调 `NVIC_EnableIRQ(UART_x_INST_INT_IRQN)`。漏了的后果：**中断永不触发、数据卡在 FIFO、一个字节都收不到，而编译期和运行期都不报任何错**。踩过两次（MCAN 一次、UART3 视觉一次）。位置：`gimbal.c: gimbal_init()` / `gyro_link.c: gyro_link_init()` / `vision_link.c: vision_link_init()` / `debug_uart.c: debug_uart_init()` |
| **速率环的延迟天花板** | 回路纯延迟 τ 决定增益硬上限：`1 + K·e^(−sτ) = 0` → K<1 稳定 / K=1 临界（`f=1/(2τ)`）/ K>1 发散。100 Hz 陀螺 τ≈10 ms → 临界 50 Hz，且 `ω_云台 = ω_车体/(1+K)`，**K=1 也只能把扰动减半**。江南方案陀螺 1000 Hz（τ≈1 ms）所以能用大增益 —— 差别全在数据率。**纯速率环实测走不通**：K=0.3 震 / 0.15 轻微震 / 0 不震但自稳也没了 |
| **卡尔曼 > 一阶低通** | 匀速目标下滞后 0 px，低通 α=0.5 是 6 px（1.27°，1.25 m 处 2.8 cm） |
| **自稳的病根在内环** | 不在外环，在 QD4310 内部速度环 —— 见 §5 内部环参数 |
| **SDK 文档 CRC 覆盖范围没写** | 控制包 4 字节 / 反馈包 9 字节这个假设是从手册推的，§7 #1 的候选原因之一 |

**其他结论**：云台**没有限位**（可 360° 连续转，找靶扫描不受角度限制）· 模块 Yaw **不慢漂**（实测）· 陀螺模块**内部已做融合滤波**（Yaw 那条路），GyroZ 是原始值。

**B 路线（只在 A 量化后明显超标才做）**：换**裸 ICM42688 直连 SPI**（模块 MCU → MSPM0 直接读；115200 UART → 8 MHz SPI；100 Hz → 可设 32 kHz；延迟 10 ms → 1 ms；可用增益上限 1.0 → ≈10）。参考实现在工作区外 `…/底盘代码/SeekFree_MSPM0G3507_Opensource_Library/project/code/ICM_42688.c`（硬件 SPI，引脚 **B23/B22/B21**，实际设 200 Hz）——**这三个引脚本工程全空着**。成本：模块 ¥20~30 + SysConfig 加 SPI + 移植驱动 + 重做零偏标定。**决策：先走 A（量化自稳精度），够指标就收工。**
